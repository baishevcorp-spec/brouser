# Roadmap

Направление развития Brouser по версиям. Критерии готовности — то, что должно
быть правдой к концу фазы (демо/ручная проверка). Детали и приоритеты
отдельных задач — в BACKLOG.md; текущее состояние — в README.md.

## v1.0 — сейчас, готово

**Цель:** рабочий мульти-аккаунтный браузер для параллельной работы с Avito.

Реализовано:

- сетка WebContentsView с раскладками 1x1 / 1x2 / 2x1 / 2x2 / 3x1 / 1x3;
- изолированные persistent-сессии `persist:profile-<id>` (куки, кэш,
  localStorage, IndexedDB) со сменой раскладки без потери данных;
- прокси на профиль (http/https/socks5/socks4, host:port, пер-протокольные
  правила), логин/пароль через событие `login` (407);
- распакованные расширения на профиль, автозагрузка при старте сессии,
  изоляция ошибок;
- отключённый фоновый троттлинг (`backgroundThrottling: false`,
  `disable-renderer-backgrounding`, `disable-background-timer-throttling`);
- отпечаток: User-Agent, таймзона через CDP (+повтор после навигаций),
  `navigator.platform`, `navigator.hardwareConcurrency`;
- config.json в userData с автосозданием (2 профиля Avito) и нормализацией;
- glass-UI (frameless, blur), темы dark/teal/light, тултипы, минимум текста;
- логирование: консоль + app.log + панель журнала, индикация ошибок;
- сохранение размеров окна и темы;
- electron-builder: NSIS (win), AppImage (linux), dmg (mac).

**Критерий готовности v1.0:** выполнен. Сборки `dist:win` / `dist:linux` /
`dist:mac` собираются, два и более аккаунтов живут одновременно в разных
ячейках с разными прокси.

## v1.1 — следующий минор: удобство оператора

**Цель:** убрать ежедневные неудобства управления профилями.

Ключевые пункты (из BACKLOG, приоритет P0/P1):

- редактирование профиля из UI;
- drag&drop сортировка профилей;
- адресная строка в шапке каждой ячейки;
- горячие клавиши (раскладки Ctrl+1..6, перезагрузка Ctrl+R);
- health-check прокси + живой индикатор статуса в ячейках.

**Критерии готовности:** смена прокси/URL/имени профиля без правки
config.json и без перезапуска; порядок видимых профилей меняется мышью;
нажатие Ctrl+3 переключает раскладку на 1x3; индикатор ячейки показывает
фактическое состояние прокси (ок / ошибка / latency).

## v1.2 — мощность сессий

**Цель:** одна сессия — несколько страниц; перенос настроек между машинами.

Ключевые пункты:

- вкладки внутри ячейки (несколько табов на сессию);
- импорт/экспорт config.json и профилей (архив с cookies);
- tray-иконка с меню (быстрое переключение раскладки, свернуть в трей);
- CI: сборка релизов GitHub Actions (матрица win/linux).

**Критерии готовности:** внутри ячейки можно открыть 2+ табов и переключать
их; полный перенос окружения профиля на другую машину одним архивом; пуш в
main автоматически выкладывает артефакты в GitHub Releases.

## v1.3 — правдоподобный отпечаток

**Цель:** закрыть основные векторы детекта минимальным расширением текущего
механизма (README, раздел «Отпечаток»).

Ключевые пункты:

- расширенный фингерпринт: WebGL vendor/renderer, canvas noise, languages,
  geolocation, screen, media devices, fonts;
- автообновления через electron-updater (источник — GitHub Releases);
- unit-тесты main-логики (vitest): parseProxy, normalizeConfig,
  normalizeUrlInput, generateProfileId.

**Критерии готовности:** отпечаток ячейки на browsertest-сайтах (amiunique
и аналоги) согласован с поданными UA/platform/tz — без «дикого» расхождения
параметров; обновление ставится в один клик; `npm test` зелёный в CI.

## v2.0 — командные сценарии

**Цель:** Brouser как инструмент команды, а не одного оператора.

Ключевые пункты:

- синхронизация профилей между машинами (общий профиль = общие куки/прокси);
- командные сценарии: общие наборы профилей, роли/права;
- возможный embedded прокси-менеджер (ротация, пул, health-check в ядре).

**Критерии готовности:** два оператора видят один и тот же набор профилей с
близкими к консистентным сессиями; администратор может выдавать/забирать
профили; пул прокси управляется из приложения.

---

Версии дальше v1.1 не привязаны к датам: порядок может меняться по спросу.
Содержимое фаз синхронизируется с BACKLOG.md.

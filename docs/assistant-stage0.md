## 1. Реестр тулов (имя — одна строка)

Каждый тул = обёртка над СУЩЕСТВУЮЩИМ методом ProfileManager/Logger: ноль
новых привилегий в main, ноль новых IPC-каналов. Параметры и ответы —
строго типизированы (Zod, этап 2); ответ тулa ≤ 4–8 КБ.

## 2. Разрешение профиля (Zero-Trust, ТЗ)

Модель НЕ передаёт profileId — main подставляет профиль сам. Порядок
разрешения аргумента `profile` (строка):

1. точное совпадение `id` в config.profiles;
2. уникальное совпадение по `name` (регистронезависимо; неоднозначность →
   error с подсказкой «уточните имя»);
3. `active` (слово-псевдоним «этот/текущий профиль») → профиль выбранной
   в сетке ячейки;
4. промах → `{ok:false, reason:"профиль не найден"}` — модель сообщает
   пользователю, без попыток угадать.

**Новая зависимость (не существовала):** «выбранный профиль» живёт только в
renderer (`selectedId` в renderer.ts) — main о нём не знает. Для пункта 3
нужен крошечный IPC `ui:selected-profile` (renderer → main, ~10 строк) —
добавится на этапе 1.

## 4. Архитектурные развилки (решение — за пользователем)

### Развилка 1: где живёт панель ассистента

- **(A) Встроенная панель справа в главном окне + резервация места в layout**
  (как панель журнала: `logPanelReserve` в layout.ts, IPC `ui:log-panel`).
  Панель всегда рядом с сеткой, не перекрывается views, сворачивается.
  ~30–40 строк в layout.ts (резерв под обе панели сразу: журнал ИЛИ ассистент,
  одновременно — сумма, ограничим: вторая панель заменяет первую).
- **(B) Отдельное BrowserWindow** (как «Настройки»): проще, ноль правок
  layout — но это «пульт в другом окне», а не панель у сетки.

**Рекомендация: (A)** — весь смысл ассистента «пульт рядом с сеткой»;
механика резерва уже отработана журналом. Если хотите минимальный риск — (B).

### Развилка 2: где настройки ассистента (Cloud/Local/Auto, ключ, голос)

- **(A) Новый раздел в существующем окне «Настройки»** — одно окно настроек.
- **(B) Отдельное окно настроек ассистента.**

**Рекомендация: (A).**

### Развилка 3: модель Ollama Cloud с надёжным tool calling

- **(A) `gpt-oss:20b`** — нативный tool calling, быстрый, экономный.
- **(B) `qwen3:32b`** — длинный контекст, стабильный формат вызовов.

**Рекомендация: (A) `gpt-oss:20b`, fallback local `qwen2.5:7b`.**
Финально проверим на этапе 1 тест-кейсом «привет» + на этапе 2 — вызовом
тула `list_profiles`.

### Развилка 4: «активный профиль» (подстановка main'ом)

- **(A) Выделение ячейки = активный профиль** (клик по шапке ячейки уже
  выделяет её; добавить IPC `ui:selected-profile` → main). Слово `active`
  в тул-аргументе разрешается в него.
- **(B) Только явное имя/id в каждом вызове** — main не хранит выделение.

**Рекомендация: (A)** — «профиль, на который я смотрю» естественен для
пульта; (B) оставляем как поведение по умолчанию до конца этапа 1, если (A)
не одобрите.

# Brouser

Brouser — десктопное мульти-аккаунтное приложение на Electron 33 и TypeScript.
Одно окно, в котором сетка изолированных веб-сессий: у каждого профиля свои куки,
кэш, localStorage, IndexedDB, свой прокси, свои расширения и свой цифровой отпечаток.

Проект создан для параллельной работы с несколькими аккаунтами Avito: расширения
автоматизации Avito требуют «видимую» активную сессию браузера, поэтому все
страницы Brouser живут в видимых ячейках сетки и никогда не сворачиваются и не
троттлятся в фоне. Подойдёт и для любых других сайтов, где нужен независимый
контекст на каждый аккаунт.

Репозиторий: https://github.com/baishevcorp-spec/brouser

---

## Возможности

- **Сетка WebContentsView.** Шесть раскладок: 1x1, 1x2 (горизонтально), 2x1
  (вертикально), 2x2, 3x1, 1x3; переключение из панели инструментов, лишние
  ячейки уничтожаются, недостающие создаются автоматически.
- **Изоляция сессий.** Отдельная persistent-сессия `persist:profile-<id>`:
  куки, кэш, localStorage и IndexedDB полностью раздельны и переживают
  перезапуск приложения.
- **Прокси на профиль.** HTTP/HTTPS/SOCKS5/SOCKS4, в том числе с логином
  и паролем; учётные данные подаются Chromium'у через событие `login`.
- **Расширения на профиль.** Распакованные Chrome-расширения (папка с
  `manifest.json`), свой набор на профиль; ошибка одного не мешает остальным.
- **Нет фонового троттлинга.** `backgroundThrottling: false` у каждого
  представления плюс `disable-renderer-backgrounding` и
  `disable-background-timer-throttling` — таймеры и WebSocket работают, даже
  когда ячейка не в фокусе.
- **Спуфинг отпечатка.** User-Agent, часовой пояс (CDP
  `Emulation.setTimezoneOverride`), `navigator.platform`,
  `navigator.hardwareConcurrency` — индивидуально на профиль.
- **Конфиг в userData.** `config.json` создаётся автоматически при первом
  запуске (2 профиля Avito), правится руками или из UI; сохраняется атомарно.
- **Glass-интерфейс.** Frameless-окно, стеклянная (blur) панель инструментов,
  три темы (dark / teal / light), минимум текста — подсказки через тултипы.
- **Логирование.** Консоль + файл `app.log` в userData + панель журнала в UI;
  на кнопке журнала появляется красная точка при свежих ошибках.
- **Сохранение состояния.** Размеры окна (width/height) и тема сохраняются в
  `config.json` и восстанавливаются при запуске.
- **Сборка electron-builder.** Windows (NSIS-установщик), Linux (AppImage),
  macOS (dmg) — одним npm-скриптом.

## Технологии

| Компонент | Версия / подход |

| Renderer | vanilla TS + HTML + CSS, без фреймворков (React/Vue не используются) |

## Быстрый старт

**Предварительные требования:** Node.js 18+ и npm.

```bash
git clone https://github.com/baishevcorp-spec/brouser.git
cd brouser
npm install
npm run dev
```

`npm run dev` = `npm run build && electron .` — скомпилирует TypeScript в
`dist/` и запустит приложение. То же делает `npm run start`.

**Что происходит при первом запуске.** Файл `config.json` не найден — Brouser
создаёт его сам с двумя профилями `avito1` и `avito2` (Avito, без прокси,
часовой пояс Europe/Moscow) и раскладкой 2x2. Файл лежит в папке `userData`:

| ОС | Путь к userData |
|---|---|
| Windows | `%APPDATA%\Brouser` |
| macOS | `~/Library/Application Support/Brouser` |
| Linux | `~/.config/Brouser` |

В этой же папке находятся `app.log` и хранилища persistent-сессий (куки, кэш
и т.д.) — не удаляйте её без необходимости. Запускается ровно один экземпляр
приложения (single instance lock): второй запуск разворачивает и фокусирует
уже открытое окно.

## Сборка релизов

| Команда | Платформа | Артефакт |
|---|---|---|
| `npm run dist:win` | Windows | NSIS-установщик (`.exe`) |
| `npm run dist:linux` | Linux | AppImage |
| `npm run dist:mac` | macOS | dmg |
| `npm run dist` | Windows + Linux | оба за один проход |

Результаты сборки складываются в папку `release/`. Иконка приложения —
`assets/icon.png` (electron-builder сам делает из неё производные размеры).
В установщик попадает только скомпилированный код (`dist/**/*` и
`package.json`); папка `extensions/` проекта упаковывается как extraResources
в `<установка>/resources/extensions` — благодаря этому относительные пути
расширений работают и в упакованном приложении.

**Про подписи.** Приложение не подписано сертификатом. На Windows при запуске
установщика SmartScreen может показать предупреждение «Система Windows
защитила ваш компьютер»: нажмите «Подробнее» -> «Выполнить в любом случае».
На macOS для неопознанного dmg потребуется правый клик -> «Открыть» либо
разрешение в «Конфиденциальность и безопасность».

## Конфигурация

Файл `config.json` лежит в userData (таблица путей выше). Полный пример
(копия `config.example.json` из репозитория):

```json
{
  "profiles": [
    {
      "id": "avito1",
      "name": "Avito Account 1",
      "url": "https://www.avito.ru",
      "proxy": "http://user:pass@185.12.34.56:8080",
      "extensions": ["./extensions/avito-helper"],
      "userAgent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/130.0.0.0 Safari/537.36",
      "timezone": "Europe/Moscow"
    },
    {
      "id": "avito2",
      "name": "Avito Account 2",
      "url": "https://www.avito.ru",
      "proxy": "socks5://192.0.2.10:9050",
      "extensions": [],
      "userAgent": "",
      "timezone": "Europe/Moscow"
    }
  ],
  "layout": "2x2",
  "theme": "dark",
  "windowBounds": { "width": 1600, "height": 900 }
}
```

### Корневые поля

| Поле | Тип | Описание |
|---|---|---|
| `profiles` | массив | Профили (таблица ниже). Порядок важен: видимы первые N. |
| `layout` | строка | Раскладка сетки: `1x1`, `1x2`, `2x1`, `2x2`, `3x1`, `1x3`. Неизвестное значение нормализуется в `2x2`. |
| `theme` | строка | Тема интерфейса: `dark`, `teal`, `light`. Неизвестное значение -> `dark`. |
| `windowBounds` | объект | `{ width, height }` — размеры окна; клампятся 720-7680 и 480-4320. |

### Поля профиля

| Поле | Тип | Описание |
|---|---|---|
| `id` | строка | Уникальный идентификатор, латиница/цифры/дефис — попадает в имя partition `persist:profile-<id>`. Дубли отбрасываются при загрузке. |
| `name` | строка | Отображаемое имя; пусто -> берётся `id`. |
| `url` | строка | URL, открываемый в ячейке. Пусто -> `https://www.avito.ru`; без схемы -> добавляется `https://`. |
| `proxy` | строка | Прокси (форматы см. [Прокси](#прокси)). Пусто или отсутствие поля — прямое соединение. |
| `extensions` | массив строк | Пути к распакованным расширениям (относительные или абсолютные). См. [Расширения](#расширения). |
| `userAgent` | строка | Свой User-Agent. Пусто — дефолтный UA Electron. |
| `timezone` | строка | Часовой пояс IANA (например `Europe/Moscow`). Пусто — системный. |
| `platform` | строка | Подмена `navigator.platform` (опционально), например `Win32`. |
| `hardwareConcurrency` | число | Подмена `navigator.hardwareConcurrency` (опционально), 1-128. |

Файл можно править руками в любом редакторе: при старте Brouser нормализует
значения (отбрасывает битые профили, дедуплицирует `id`, чинит раскладку и
размеры). Изменения из файла применяются после перезапуска приложения;
операции, сделанные через UI (добавление/удаление профилей, раскладка, тема),
применяются сразу и сохраняются в файл немедленно (атомарная запись tmp +
rename — файл не побьётся при падении).

## Прокси

Строка `proxy` профиля разбирается парсером (`src/main/proxy.ts`).
Поддерживаемые форматы:

| Формат | Пример | Примечание |
|---|---|---|
| HTTP с логином/паролем | `http://user:pass@185.12.34.56:8080` | порт по умолчанию 80 |
| HTTPS | `https://user:pass@host:443` | порт по умолчанию 443 |
| SOCKS5 | `socks5://user:pass@192.0.2.10:9050` | порт по умолчанию 1080 |
| SOCKS4 | `socks4://host:1080` | схема передаётся как есть |
| SOCKS-алиасы | `socks://...`, `socks5h://...` | нормализуются в `socks5` |
| Прямая запись | `host:port` | трактуется как Chromium proxyRules |
| Пер-протокольные правила | `http=host:80;https=host:80` | формат proxyRules Chromium |

Прямое соединение — пустая строка или отсутствие поля `proxy`.

**Как работает авторизация.** Формат Chromium `proxyRules` не допускает
встроенных логина/пароля, поэтому Brouser вырезает учётные данные из URL и
держит их в памяти. При первом 407-вызове прокси-сервера Chromium вызывает
событие `app('login')`, обработчик подставляет сохранённые логин и пароль.
То же самое происходит для каждого профиля независимо.

**Отказоустойчивость.** Ошибка разбора строки или установки прокси не роняет
приложение и не мешает остальным профилям: в журнал пишется предупреждение
(«не удалось разобрать строку прокси — используется прямое соединение»), и
ячейка работает через прямое соединение. Проблемы соединения видны как
белая/пустая ячейка и записи в журнале.

## Расширения

Расширения грузятся как **распакованные папки** — каталог с `manifest.json`
внутри. Manifest V2 поддерживается полностью; MV3 в целом поддерживается
Electron/Chromium на момент версии 33, но с ограничением на
`service_worker`-background (см. BACKLOG).

### Как добавить

1. Положите распакованную папку расширения в `extensions/` рядом с проектом
   (dev-режим) и укажите относительный путь в `config.json`:

   ```json
   "extensions": ["./extensions/avito-helper"]
   ```

   либо укажите абсолютный путь: `"extensions": ["/opt/extensions/avito-helper"]`.
2. Перезапустите Brouser (или добавьте профиль через UI, указав пути в поле
   расширений — строки разделяются переводом строки, `;` или `,`).

Относительные пути ищутся по порядку:

1. папка userData (рядом с `config.json`);
2. `resources/extensions` — в упакованном приложении (extraResources);
3. рабочая директория процесса;
4. корень приложения (в dev — папка проекта).

### Важное поведение

- Расширения **не персистентны между запусками** Chromium-хранилищем сессии:
  Brouser сам перезагружает их при создании сессии профиля при каждом старте.
- Ошибка загрузки одного расширения (путь не найден, битый manifest)
  записывается в журнал с точной причиной и **не мешает** загрузке остальных
  расширений и работе профиля.
- Набор расширений индивидуален для каждого профиля.

### Минимальный manifest.json (MV3)

```
extensions/
└─ avito-helper/
   ├─ manifest.json
   └─ icon.png (или другой иконки из manifest)
```

```json
{
  "manifest_version": 3,
  "name": "avito-helper",
  "version": "1.0.0",
  "description": "Пример расширения для Brouser",
  "background": {},
  "action": {}
}
```

## Отпечаток (fingerprint)

Что подменяется и каким механизмом:

| Параметр | Механизм | Момент применения |
|---|---|---|
| User-Agent | `ses.setUserAgent(...)` | при создании сессии профиля |
| User-Agent + `navigator.platform` | CDP `Network.setUserAgentOverride` (задаёт и UA, и platform до выполнения скриптов страницы) | при создании представления |
| Часовой пояс | CDP `Emulation.setTimezoneOverride` (IANA-идентификатор) | при создании и повторно после каждой навигации (override привязан к процессу рендера и может слетать) |
| `navigator.platform` | инъекция `Object.defineProperty` через `executeJavaScript` | после события `dom-ready` |
| `navigator.hardwareConcurrency` | инъекция `Object.defineProperty` через `executeJavaScript` | после события `dom-ready` |

**Честное предупреждение.** Это *минимальный* спуфинг, а не полная
антидетект-защита: WebGL (vendor/renderer), canvas, шрифты, языки, геолокация,
медиа-устройства и экран **не подменяются**. Серьёзные проверки отпечатка на
стороне сайта увидят остальную часть окружения как есть. Полный план по
фингерпринту — в BACKLOG.md.

## Архитектура

Структура проекта:

```
brouser/
├─ package.json              # скрипты, зависимости
├─ tsconfig.json             # strict TypeScript, выход в dist/
├─ electron-builder.yml      # конфиг упаковки (win/linux/mac)
├─ config.example.json       # пример конфига (без secret-данных)
├─ scripts/
│  └─ copy-assets.js         # копирование index.html/styles.css в dist/renderer
├─ src/
│  ├─ main/                  # main-процесс Electron
│  │  ├─ index.ts            # точка входа: окно, IPC, жизненный цикл
│  │  ├─ profileManager.ts   # ядро: сессии, представления, прокси, отпечаток
│  │  ├─ config.ts           # чтение/запись/нормализация config.json
│  │  ├─ logger.ts           # логгер (консоль + app.log + UI)
│  │  ├─ proxy.ts            # разбор строки прокси
│  │  └─ types.ts            # общие типы, LAYOUTS, THEMES, BrouserApi
│  ├─ preload.ts             # contextBridge -> window.brouser
│  └─ renderer/              # vanilla TS-интерфейс (без фреймворков)
│     ├─ index.html
│     ├─ renderer.ts
│     └─ styles.css          # glass-дизайн, темы dark/teal/light
├─ extensions/               # распакованные расширения (extraResources)
└─ assets/
   └─ icon.png               # иконка приложения
```

**Ключевая идея координат.** Окно frameless (`frame: false`), вся рамка
рисуется renderer'ом. Renderer рисует сетку и после каждой перерисовки
измеряет элемент `.cell-body` каждой ячейки, затем отправляет прямоугольник
(`Rect` в DIP-координатах = CSS-пиксели при zoom 1) в main по каналу
`view:set-bounds`. Main создаёт `WebContentsView` по запросу и выставляет ему
`setBounds(...)` ровно по присланным координатам. Благодаря этому панель
инструментов (которая сама является drag-region для перетаскивания окна)
никогда не перекрывает ячейки, а ячейки всегда видимы — расширения Avito
видят «живую» видимую сессию.

Main-процесс владеет всем: окном, сессиями, представлениями и конфигом.
Renderer не получает Node — только безопасный IPC-мост `window.brouser`
(contextIsolation + sandbox включены).

## IPC-контракт

Renderer -> main (через `ipcRenderer.invoke`, методы `window.brouser`):

| Канал | Метод API | Назначение |
|---|---|---|
| `state:get` | `getState()` | полное состояние `AppState` |
| `profile:add` | `addProfile(input)` | добавить профиль (валидация в main) |
| `profile:remove` | `removeProfile(id)` | удалить профиль и его представление |
| `layout:set` | `setLayout(layout)` | сменить раскладку сетки |
| `theme:set` | `setTheme(theme)` | сменить тему |
| `views:reload-all` | `reloadAll()` | перезагрузить все представления |
| `view:reload` | `reloadView(id)` | перезагрузить одну ячейку |
| `view:devtools` | `openDevTools(id)` | DevTools ячейки в отдельном окне (detach) |
| `config:save` | `saveConfig()` | принудительно сохранить config.json |
| `window:minimize` | `minimize()` | свернуть frameless-окно |
| `window:toggle-maximize` | `toggleMaximize()` | развернуть/восстановить окно |
| `window:close` | `close()` | закрыть окно (= выход) |

Renderer -> main, односторонняя отправка (`ipcRenderer.send`):

| Канал | Метод API | Назначение |
|---|---|---|
| `view:set-bounds` | `sendViewBounds(id, rect)` | прямоугольник ячейки; main позиционирует/создаёт WebContentsView |

Main -> renderer (события, подписки через `onProfilesUpdated` /
`onLayoutChanged` / `onLogMessage`):

| Канал | Payload | Назначение |
|---|---|---|
| `profiles-updated` | `AppState` | любое изменение профилей/раскладки/темы |
| `layout-changed` | `LayoutId` | смена раскладки (renderer перестраивает сетку) |
| `log-message` | `LogEntry` | новая запись журнала (трансляция всех логов) |

Полное состояние — `AppState`:

```ts
interface AppState {
  profiles: ProfileState[];  // id, name, url, hasProxy, proxyScheme, extensions[],
                             // timezone, userAgentSet, platform, hardwareConcurrency, visible
  layout: LayoutId;          // текущая раскладка
  theme: ThemeId;            // dark | teal | light
  capacity: number;          // число ячеек текущей раскладки
  logs: LogEntry[];          // последние записи журнала (до 60)
}
```

## Правила жизни профилей

- Видимы (и вообще создаются) только **первые N** профилей из массива
  `profiles`, где N = число ячеек текущей раскладки (`1x1` -> 1, `1x2`/`2x1`
  -> 2, `3x1`/`1x3` -> 3, `2x2` -> 4).
- Остальные профили **не создаются** до смены раскладки (или удаления лишних
  профилей сверху списка).
- При смене раскладки лишние представления уничтожаются, недостающие
  создаются, когда renderer пришлёт координаты новых ячеек.
- Сессия каждого профиля persistent (`persist:profile-<id>`): куки, кэш,
  localStorage, IndexedDB хранятся на диске и **переживают перезапуск**
  приложения. Данные невидимых профилей также сохраняются — сессия живёт на
  диске независимо от того, было ли создано представление.

## Логирование

Каждая запись журнала попадает в три места одновременно:

1. консоль main-процесса;
2. файл `app.log` в userData (сброс записи не роняет приложение);
3. renderer — канал `log-message`, панель журнала в UI.

Уровни: `info` / `warn` / `error`. В UI-панели отображается до 60 последних
записей (кольцевой буфер хранит 300). Кнопка журнала получает красную точку,
когда появляются свежие ошибки. Прокси- и расширения-ошибки пишутся с
префиксом `[profile-id]`, так что причину проблемы конкретной ячейки видно
сразу.

## Troubleshooting

- **Белая/пустая ячейка.** Чаще всего прокси недоступен или неверные учётные
  данные. Откройте панель журнала — там будет `did-fail-load` с кодом ошибки
  либо запись «учётные данные прокси предоставлены». Проверьте прокси в
  стороннем клиенте.
- **Расширение не загрузилось.** Точная причина (путь не найден / ошибка
  manifest) пишется в журнал с префиксом `[id]`. Проверьте, что указана
  распакованная папка с `manifest.json`, и что путь существует в одной из
  четырёх точек поиска (см. [Расширения](#расширения)).
- **«Прокси не работает», хотя логин/пароль верные.** Если в логине или
  пароле есть спец-символы (`@`, `:`, `/` и т.п.), их нужно URL-кодировать:
  `@` -> `%40`, `:` -> `%3A`, `#` -> `%23`, `?` -> `%3F`, `%` -> `%25`.
  Пример: `http://user%40mail:pa%23ss@host:8080`.
- **Пропали куки/сессии аккаунта.** Не удаляйте папку userData и не меняйте
  `id` существующего профиля — `id` входит в имя partition
  (`persist:profile-<id>`), смена `id` создаёт новую пустую сессию.
- **Полный сброс.** Закройте Brouser и удалите папку userData (таблица путей
  в разделе «Быстрый старт») — при следующем запуске заново создастся
  `config.json` с двумя дефолтными профилями.
- **Конфиг повреждён / битый JSON.** Brouser откатится к значениям по
  умолчанию и запишет ошибку в журнал; исправьте синтаксис файла.

## Разработка

```bash
npm run dev        # сборка + запуск (основной цикл разработки)
npm run typecheck  # tsc --noEmit, проверка типов без emit
npm run build      # tsc + copy-assets.js
```

Структура сборки после `npm run build`:

```
dist/
├─ main/           # index.js, profileManager.js, config.js, logger.js,
│                  # proxy.js, types.js
├─ preload.js
└─ renderer/       # index.html, styles.css (+ renderer.js)
```

`tsc` не копирует статические файлы — `scripts/copy-assets.js` переносит
`index.html` и `styles.css` в `dist/renderer/`. Для пересборки после правок
`src/` достаточно повторного `npm run dev`.

**Иконка.** Источник — `assets/icon.png` (используется и как icon приложения,
и в конфигах win/linux/mac electron-builder). Чтобы заменить иконку,
подготовьте PNG не менее 512x512 и положите его в `assets/icon.png`, затем
пересоберите релиз (`npm run dist:*`) — производные размеры electron-builder
сгенерирует сам.

**DevTools ячейки.** Кнопка в шапке ячейки открывает DevTools в отдельном
окне (mode: `detach`), чтобы инспектор не перекрывал сетку. Логи dev-запуска
смотрите в консоли, из которой запущен `npm run dev`, или в `app.log`.

## Репозиторий

Remote: https://github.com/baishevcorp-spec/brouser

Публикация из локальной копии:

```bash
git add .
git commit -m "..."
git push -u origin main
```

Если push запрашивает аутентификацию, задайте токен прямо в URL remote
(PAT с правами `repo`):

```bash
git remote set-url origin https://<TOKEN>@github.com/baishevcorp-spec/brouser.git
git push -u origin main
```

После успешного пуша токен можно убрать из URL:
`git remote set-url origin https://github.com/baishevcorp-spec/brouser.git`.
